# Sound Pad GUI/UX 監査とリファイン方針

## 結論

現行アプリの核である「ワンクリック試聴」と「ファイル名コピー」は維持する。一方、現在はフォルダ、案件、お気に入り、タグ、SE/BGM、再生状態が同じ階層に混在している。リファインでは次の階層へ整理する。

1. **案件** — 使用するフォルダ、タグ語彙、お気に入り、セットリストのスコープ
2. **作業モード** — SE / BGM
3. **ライブラリ** — フォルダ、検索、タグによる絞り込み
4. **選定結果** — お気に入り、候補、セットリスト、使用済み

「お気に入り管理画面」を独立したモーダルとして持つのではなく、通常画面内の保存済みビューとして扱う。タグ編集も小モーダルを重ねず、右インスペクタまたはインライン編集へ移す。

## 現行画面の主な問題

### P0: 再生バーが操作不能になる可能性

- シーク中フラグを `mousedown` / `mouseup` だけで管理している。ウィンドウ外でボタンを離す、キーボードで操作する、ポインターイベントが欠落する、といった場合に `data-dragging` が残り、以後200ms更新がシークバーへ反映されない。
- `mouseup` と `change` の両方でシーク処理を発火するため、同じ操作で二重に再生ソースを作り直す可能性がある。
- シークは一時停止中でもバックエンド側で必ず再生を開始する。UIの一時停止表示と実再生が食い違う。
- 200msの `setInterval(async ...)` は前回呼び出しの完了を待たないため、応答順が逆転すると古い状態で表示を上書きできる。
- お気に入り画面からの再生では既知のdurationを渡さず、`lastPlayedDuration` も更新しないため、停止後の表示状態が通常一覧からの再生と一致しない。
- 再生位置は実際のSink位置ではなく壁時計から算出しており、デコード開始・シーク・デバイス遅延と表示がずれる余地がある。

**方針:** フロント側に単一の `PlaybackState` を設け、requestAnimationFrameまたは直列ポーリングで描画する。シークは `pointerdown` / `pointerup` / `pointercancel` とキーボードを扱い、1回だけcommitする。バックエンドは再生セッションIDを返し、古いイベントを無視できるようにする。

### P0: タグ編集がメイン画面へ即時反映されない

タグ保存後に更新しているのは、お気に入りモーダル内の一覧とタグ選択肢だけである。メイン一覧の `renderAudioFiles()` とメイン側フィルターの `updateMainTagFilterOptions()` が呼ばれていない。そのためデータ自体は保存済みでも、通常画面では再起動まで古い表示が残る。

**方針:** データ変更後に画面ごとの再描画関数を個別に呼ぶのではなく、favorites/tagsストアを更新し、その購読先を一括更新する。最低限の修正ではタグ保存後にメイン一覧とメインタグ候補も再描画する。

### P1: 案件という最上位コンテキストが存在しない

- ブックマークはフォルダへのショートカットであり、「案件名」「案件で使う複数フォルダ」「案件固有のタグ」「セットリスト」を束ねられない。
- 現在地は長いパンくずで示すのみで、どの案件の選定中なのかが常時認識できない。
- 履歴とブックマークのドロワーはナビゲーション、案件切替、情報表示を兼ねており役割が曖昧。

**方針:** `Project` を導入し、常時表示の案件スイッチャーを最上段に置く。プロジェクトは複数ライブラリルート、タグスコープ、SE/BGMお気に入り、セットリストを参照する。

### P1: SEとBGMの作業目的が混在

- お気に入りは単一Map・単一JSONで、SE/BGMの区別がない。
- タグも全ファイルから作るグローバル配列で、現在の案件・フォルダ・メディア種別によるスコープがない。
- BGMに必要な「次曲比較」「使用済み」「並び順」「合計時間」「重複警告」がない。

**方針:** SE/BGMを明示的なモードとして分離する。お気に入りは同じデータモデルでも `media_type` と `project_id` を持たせ、UIでは必ず分ける。タグ候補は `案件 × メディア種別` を既定スコープとし、「共通タグを表示」で拡張できるようにする。

### P1: モーダルの多重化で選定文脈が切れる

通常画面の上にお気に入り管理モーダル、その上にタグ編集モーダルが重なる。背後の再生状態・選択対象・現在フォルダが見えづらくなり、比較試聴しながら整理する用途と相性が悪い。

**方針:** お気に入りは左の保存済みビュー、タグ編集は右インスペクタへ統合する。一括操作時のみ選択ツールバーを出す。

### P1: マスターボリュームがない

バックエンドのSinkにvolume状態がなく、再生ごとにOS既定音量で鳴る。

**方針:** `AudioPlayer` に0.0–1.0のvolumeを保持し、新しいSink作成時にも適用する。UIは下部トランスポートに常設し、値を永続化する。ミュートは直前値を保持する。

### P2: 一覧の操作優先度が不明瞭

- 再生、チェック、スター、コピー、タグ、ファイルコピーが同じ行に並び、試聴という主操作が相対的に弱い。
- チェックはファイルコピー用、お気に入り画面では一括タグ用と意味が変わる。
- 青い「再生」ボタンが全行で強く主張し、長いリストでは視覚ノイズになる。
- タグが同じ色・同じ形で並ぶため、意味の違いを瞬時に判別しづらい。

**方針:** 行全体または先頭の固定ホットスポットを試聴操作にする。副操作は選択行・hover・右インスペクタへ寄せる。選択モードは明示的に開始する。

### P2: フィルターが肥大化する

すべてのタグを1つのselectへ平坦に追加しているため、増えるほど探索時間が伸びる。フォルダフィルターもパス文字列の一覧であり、案件や種別との関係が分からない。

**方針:** 検索可能なファセットにし、ムード・用途・感情・ジャンルなどのタググループを持たせる。最近使ったタグと案件内タグを先に出す。タグ管理画面では使用数、未使用、統合、名称変更を扱う。

### P2: BGM選定の記録が残らない

お気に入りだけでは「好きな曲」と「今回使う候補」と「採用済み」を区別できない。動画内や案件間の重複も追えない。

**方針:** `Setlist` と `SetlistItem` を導入し、候補 / 採用 / 使用済み、順序、想定尺、メモを保持する。同一ファイルの重複、直近案件での使用、同一セット内の重複を警告する。

## 推奨情報設計

```text
案件
├─ ライブラリルート（複数）
├─ SE
│  ├─ フォルダ / 検索 / タグ
│  ├─ お気に入り
│  └─ 選定トレイ
├─ BGM
│  ├─ フォルダ / 検索 / タグ
│  ├─ お気に入り
│  └─ セットリスト（候補 / 採用 / 使用済み）
└─ 案件設定（タグスコープ、音量、既定表示）
```

## コンセプト3案

### A. Studio Deck / 統合編集卓型

- 暗色・高密度の3ペイン構成。
- 案件、ライブラリ、中央一覧、セットリスト、インスペクタを一画面に統合。
- SE/BGMの両方を同じ操作骨格で扱いやすい。
- 多機能化しても破綻しにくい一方、初見の情報量は多い。

画像: `concept-a-studio-deck.png`

### B. Library Workbench / BGMライブラリ型

- 明色・表形式で、長時間の比較と整理に向く。
- BPM、ムード、最終使用案件、セットリスト、タグ編集を同時に確認。
- BGM選定の新しいユースケースに最も素直。
- SEの瞬間的な連打試聴にはA/Cより一手多く感じる可能性がある。

画像: `concept-b-library-workbench.png`

### C. Cue Board / SEキューボード型

- 物理サンプラーに近い高密度パッドとキーボードショートカット。
- 超短尺SEを連続で確認する当初コンセプトを最も強く保つ。
- 右の選定トレイからBGMセットリストへも到達できる。
- 長尺BGMのメタデータ比較はBほど得意ではない。

画像: `concept-c-cue-board.png`

## 推奨案

**骨格はA、SE表示はC、BGM表示はB** の組み合わせを推奨する。

- 共通シェル: Aの案件スイッチャー、左ナビ、右選定ペイン、下部トランスポート
- SEモード: Cのパッド/高密度キュー表示
- BGMモード: Bのメタデータ表、使用履歴、セットリスト
- タグ編集: Bの右インスペクタ方式
- 視覚テーマ: A/C寄りの暗色を既定とし、必要ならライトテーマを追加

これなら「SEワンクリック試聴」という原点を弱めず、BGM選定を後付け画面ではなく専用ワークフローとして育てられる。

## 実装順

1. 再生状態の単一化、シーク修正、マスターボリューム
2. タグ即時反映とタグストアの整理
3. Project / media_typeを含むデータモデルと既存データ移行
4. 共通シェル（案件、SE/BGM、左ナビ、右ペイン、下部プレイヤー）
5. SEキュー表示
6. BGMセットリストと重複・使用履歴
7. タグ管理（グループ、名称変更、統合、未使用タグ削除）
